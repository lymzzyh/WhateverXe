# UHD770 source branch

This branch carries optional UHD 770 adaptations on top of WEX 0.7.0. The
upstream pmap call-target and argument-contract checks remain in use.

The local page-validator and gamma adaptations require physical Intel
`8086:4680`, revision `0c`, no effective device-ID override, and this exact kernel:
(The normal PCI `device-id` property equal to the physical ID is accepted.)

```text
Darwin Kernel Version 25.6.0: Mon Oct 12 00:33:09 PDT 2026; root:xnu-12377.161.15.701.48~2/RELEASE_X86_64
```

`-wex-tahoe-abi` enables that path. The original seven-argument page validator
runs first; all three validation outputs are preserved. Only accepted 4096-byte
pages with exact file offsets and SHA-256 identities can be changed. The
callback performs no filesystem access, allocation or IORegistry publication.
The complete page is checked again under the kernel write lock. Gamma endpoint
conversion remains limited to completed uploads belonging to the admitted GPU.
The real SMBIOS identity is not changed.

Two additional opt-ins, `-wex-adls-context-cache` and
`-wex-adls-bcs-native-wait`, retain their physical GPU, revision, Tahoe, host
scheduler and exact driver-layout guards. Both also require the successful
`-wex-tahoe-abi` hook receipt, so broader upstream OS support cannot widen this
branch's local kernel scope. They are experimental mitigations;
they do not establish that GPU hangs are fixed. Neither is enabled by default.

The Metal and TGLVA page adaptations identify the older Graphics 0.3.2 pages.
Graphics 0.4.0 has its own servicing-build support: changed pages intentionally
do not match these legacy hashes. A zero legacy patch count with the newer
payload is therefore not, by itself, a failure. The AppleGVA and gamma paths
retain their independent guards. A successful build does not qualify a new
WEX/Graphics combination on hardware.

## Rebuild

Use macOS, Xcode Command Line Tools and Python 3.10 or newer. Prepare the same
public dependencies pinned by CI, starting in the repository root:

```sh
git clone https://github.com/acidanthera/MacKernelSDK.git MacKernelSDK
git -C MacKernelSDK checkout 05094e5e88cec7caedbfb35e8449ed0db94bf95b
git clone --branch 1.7.2 --depth 1 https://github.com/acidanthera/Lilu.git build/dependencies/Lilu
mkdir -p Lilu.kext/Contents/Resources
ln -s "$PWD/build/dependencies/Lilu/Lilu/Headers" Lilu.kext/Contents/Resources/Headers
ln -s "$PWD/build/dependencies/Lilu/Lilu/Library" Lilu.kext/Contents/Resources/Library
python3 tools/test.py
python3 tools/build.py --output build/UHD770-DEBUG
python3 tools/build.py --release --output build/UHD770-RELEASE
```

For existing dependencies, pass `--sdk` and `--lilu` to the builder instead.
Both configurations produce WEX and Compat, a source/hash manifest and WEX stack
budget checks. No private Apple reference page or signing key is needed to
compile WEX. The built Compat is an unsigned development output; the Graphics
package continues to use its complete, preserved Mod-signed payloads.

CPU tests include independent SHA-256 vectors, synthetic page-validator replay,
gamma ownership/completion, ContextCache admission and BCS installation failures.
Synthetic replay substitutes only the expected page identities in temporary
test headers; the callback and matching/patching code are taken from production.
Optional exact-page replay accepts private `metal.bin`, `video.bin` and `gva.bin`
files, each exactly 4096 bytes with the hashes embedded in the source:

```sh
python3 tests/uhd770_callback.py --reference-pages /path/to/private/pages
python3 tests/adls_bcs_wait_native.py /path/to/qualified/AppleIntelTGLGraphics
```

Keep these inputs and generated results outside Git. Native replay executes
qualified code on the CPU; it does not exercise GPU scheduling or prove runtime
stability. Packaging and signature provenance are documented in WhateverXe-Graphics.
